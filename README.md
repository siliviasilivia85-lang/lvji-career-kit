## 为什么做履迹

很多人开始认真思考职业的下一步时，眼前这份工作已经难以带来新的成长。

等到需要下一份工作，才匆忙翻找旧项目、补写简历、重新考虑方向。过去做过不少事，学过不少东西，记录却散落各处，很难说清它们让自己积累了什么。想尝试几类岗位，又要分别准备不同的简历。求职很容易变成“为了找工作而找工作”：还没有看清下一步，就已经开始赶路。

但能力的积累有自己的时间。简历可以在几天里修改，一段扎实的实践、一项可以迁移的能力，却需要在日常中慢慢积累出来。AI 正在改变岗位的边界和要求，职业准备也需要更早地进入我们的工作与生活。

**履迹想帮助你梳理一条具有成长性的职业发展链路：让过去的积累有处可寻，让未来的目标落到当下，也让今天的努力能够通向下一次选择。**

它为你已有的 Agent 提供一套思路与工具，让它成为你的专属职业发展顾问。通过持续整理经历、拆解行动、回看成果和跟进机会，把零散的职业准备，逐渐接成一个有方向、能积累、可延续的过程。

## 把过去、现在和未来接起来

### 过去：从走过的路里，找到成长的线索

过往的工作、项目、学习路径和经历，值得被好好保存，也值得不时回看。履迹按板块整理这些材料，保留原件与来源，允许你随时补记遗漏的细节。Agent 据此帮助你审视已经形成的经验、偏好和可迁移能力；新的职业选择，也可以从一条与过去不同的路开始。

### 现在：让长远的方向，在日常里有一个落点

成长需要放进真实的生活：手头还有工作，一周能留出的时间有限，计划也会被临时的事情打断。履迹结合你当下的处境与可投入时间，把想法拆成具体项目、阶段成果和日周月行动，让通向未来的准备融入日常的碎片与间隙。推进不顺时，可以缩小一步、调整节奏，再决定什么值得继续。

### 未来：让多个目标，共享一份持续生长的积累

未来可以有不止一个方向。它们需要的能力往往有交集，同一个项目、一段学习或一次工作实践，可以同时为不同的可能性做准备。履迹帮助你梳理这些连接，把目标要求拆回当下的能力积累与行动，而不是为每个岗位重新开始。

真正进入求职期，再从过去与现在的积累中选择适合的内容，针对不同岗位、公司制作和管理简历版本，准备面试，记录投递进展、交流体验与反馈。新的反馈会成为重新审视方向、调整当下行动的依据。

这条链路也需要真实的证据。一个任务完成后，可以先留下普通记录；作品、实际产出和反馈经你核对，才能说明它支持哪些能力。你选择保存的成果，会继续用于后续规划、简历和面试。**每次实践留下积累，每次选择带回新的认识，职业发展才有了连续的轨迹。**

这些连接可以逐步建立，方向也可以随着实践调整。重要内容会先形成具体草稿，由你核对和决定是否保存。

## 快速上手：先整理一段经历

第一次使用，先挑一段自己熟悉的经历：一个做过的项目、一段工作、一项学习。可以用已有简历的一部分、项目复盘或学习笔记；手边没有文档，也可以先把经过写下来。不必一次准备完整的职业档案。

眼下没有过往资料，也可以从现在想做的事开始讨论。经历以后再补；一个尚未定下来的念头，也可以先独立保存。

1. **建立自己的工作区。** 下载本包，在常用 Agent 中打开或授权访问该文件夹，让它读取根目录的 `AGENTS.md` 和 `SKILL.md`，选择中文或英文指南建立个人工作区并展示资料地图。中文入口是“从这里开始.md”，英文入口是 `START-HERE.md`；只需首次启用，之后正常交流即可。完整文件流程需要 Agent 能读写、执行本地文件，以及 Python 3.10+。
2. **把这段经历的材料放进去。** 放到工作区的 `past/materials/`；暂时不知道怎么分类，就放到 `inbox/`。也可以把附件交给 Agent，请它导入并梳理。你直接放入的原件保留原名原位，普通笔记、PDF、Word或图片不需要填写内部字段；能否可靠理解附件取决于所用 Agent。
3. **一起梳理和校对。** Agent 提取你做了什么、承担什么、留下哪些产出，给出经历草稿，标明依据与待了解的内容。你补充遗漏、纠正理解，确认后保存为可读的 Markdown 记录；原件仍然保留。你也可以直接编辑记录正文；任务的日期和状态有专门字段，交给 Agent 调整最省心。
4. **在总览中看一遍。** 请 Agent 生成并展示工作台，在“总览 → 来路与当前理解”打开刚整理的记录，查看正文和来源。发现不准确的地方，可以交给 Agent 修改，或自己改 Markdown 后重新生成页面。目前网页用于查看与选择，修改经 Agent 或文件完成，不会在网页里直接保存。
5. **从这段积累接出下一步。** 再结合目前想做的事和可投入时间，讨论一个值得推进的项目或行动。它可以关联未来方向，也可以先独立进行；决定保存后，再到统一计划查看安排。

第一次梳理结束，你应该能找得到原件、看得懂整理后的记录、知道如何纠正它，并能从这里继续下一次讨论。想先用虚构材料熟悉过程，可让 Agent 按[试用说明](examples/try-it.md)在新临时目录操作。

## 日常材料放在哪里

以下路径都在个人职业工作区内。新用户建议使用Skill安装目录之外的 `~/lvji-workspace/`；已有工作区继续沿用原路径，不自动搬迁。

| 手里的内容 | 放入位置 |
| --- | --- |
| 旧简历、证书、过往工作与项目材料、学习笔记 | `past/materials/`，可按主题自建子目录 |
| 当前公共资料，或某个正在推进的事项的材料 | `present/materials/` 或 `present/items/<item>/materials/` |
| 还没确定归属的 JD、职业方向资料 | `future/materials/` |
| 某个方向或公司机会的 JD、截图和反馈 | 对应方向或机会下的 `materials/` |
| 暂时不知道怎么分类的内容 | `inbox/` |

工作区的 `MAP.md` 是给你看的资料地图，`AGENT-MAP.md` 是 Agent 的读取导航，两者来自同一份清单。你可以直接放文件；Agent 下次处理相关问题时检查该范围的变化，按需读取，再与你核对整理结果。发现文件、读懂材料、确认经历是不同的步骤。

分区说明、资料地图和首用入口会按中文或英文生成。底层路径统一使用 `past/`、`present/`、`future/`，地图会用所选的中文或英文解释每处放什么；自己的文件名和子目录可以用中文。这样换语言或换 Agent 时，原有引用和版本仍能接上，不需要搬动资料。

## 现在有哪些可视化

**主工作台是同一个网页里的四个视图，统一生成在个人工作区的 `views/overview.html`。** 打开这一个文件，就可以通过顶部标签切换。

| 视图 | 能看到什么 | 在哪里继续 |
| --- | --- | --- |
| **总览** | 正在推进的事项、今日行动、最近学习与工作进展，以及可展开的已完成/暂停事项、想法与阶段回看 | 打开事项与来源；过往记录在“来路与当前理解”中展开 |
| **统一计划** | 日行动、周日历、月日历、年月份卡片，以及对应的计划说明与实际记录 | 切换时间尺度、查看行动；需要改安排时交给 Agent |
| **所向** | 横向排列的职业方向、相关要求与证据支持、资料充分度和个人偏好 | 排序比较，进入方向和公司 JD 详情，查看简历与面试材料 |
| **投递进展** | 各公司机会所在阶段、下一步、历史节点、实际使用的简历版本与反馈 | 查看全部机会，或按方向、公司、机会及阶段筛选；没记录所用版本时明确留空 |

还有几类内容容易被误认为独立面板：

- **过去的经历**在总览内展开，目前没有独立的“过去”一级网页；原始材料和整理状态从 `MAP.md` 查找。
- **面试材料**在所向或投递进展的方向、公司机会详情内打开，没有另一套面试首页。
- **网页简历**是单独留版的 HTML。岗位通用版放在 `future/roles/<role>/common/resumes/<version>/`，公司版放在该公司机会的 `resumes/<version>/`；可从详情里的“已有简历版本”进入。六种模板是六种排版，不是六个工作台。

页面由已保存的文件按需生成。筛选、排序和查看可以在页内完成；正文、任务日期或投递状态的修改，交给 Agent 展示差异、确认保存后再刷新，也可以直接修改 Markdown。页面上的“请 Agent 调整”是复制请求的兼容入口，日常不必从网页复制指令；当前页面不会直接写回资料，也没有拖拽排期保存。

筛选只改变眼前显示，完整快照仍含生成时读取的职业资料；它不是按岗位隔离的分享链接。需要对外展示时，先让 Agent 生成内容范围明确的独立材料。

完整的入口、生成方式和实际支持的操作，集中在[可视化说明](references/views.md)。模板源码是 `assets/md_workspace.html`，需要填入工作区数据后才能成为可用页面；不必直接打开模板找自己的资料。

### 简历样式可以先预览

制作简历前，可以让Agent生成一份虚构的样式画廊：同一份经历展示为简介侧栏、经典单栏、证据档案、简洁文本、项目优先和经历优先六种排版，均可切换两张AI生成的虚构头像，也可以不放头像。选好后告诉Agent样式名，再换成自己的经历与照片。

画廊还收录7个GitHub网页简历参考，提供官方样例、适用场景和许可证链接。它们是外部参考，和六种已内置排版分开展示。具体入口与生成方法见[简历流程](references/resume.md)。

## 先看虚构演示

本地演示中的对话明确标注为虚构示例。演示把“梳理经历 → 探索方向 → 拆解行动 → 留下积累”串起来，再打开计划、方向和简历查看结果；演示网页本身不运行在线Agent，也不保存访客资料。

维护者可以生成适合静态托管的版本：

```text
python3 scripts/demo_site.py --output _site
```

输出目录必须全新；演示只含虚构只读页面和本地资产，不导出本机路径、个人工作区或运行历史。仓库建立后，可在Pages中选择GitHub Actions，再手动运行[演示发布工作流](.github/workflows/pages.yml)。只上传 `_site/`，不发布整个仓库或职业资料目录。准备好工作流不代表已有在线站点。

## 文件怎样留存

```text
lvji-career-kit/              下载的 Skill 包
├── README.md                给使用者的说明
├── README.en.md             English guide
├── README.ja.md             日本語のガイド
├── README.ko.md             한국어 안내
├── README.es.md             Guía en español
├── SKILL.md                 Agent 的工作入口
├── AGENTS.md                文件夹协作入口
├── references/              资料、规划、方向、简历、面试与视图的工作流
├── prompts/                 画像、差距分析、面试准备与复盘提示词
├── scripts/                 本地文件助手
├── assets/                  可修改的页面模板
└── examples/                少量虚构试用材料

~/lvji-workspace/             个人职业资料，与Skill安装目录分开，不随源码发布
├── MAP.md               资料地图
├── AGENT-MAP.md         Agent 导航
├── 从这里开始.md         中文工作区首用入口；英文为START-HERE.md
├── inbox/               暂不确定分类的材料
├── past/                过往经历与学习积累
├── present/             当前事项、行动、计划、想法与阶段回看
├── future/roles/        方向、公司机会、简历与面试材料
├── views/overview.html  统一可视化工作台
└── .luji/               工具维护的草稿、历史与导航缓存
```

经历和行动各有自己的主文件；不同方向和日周月计划引用同一份积累。换一个对话时，Agent 从已保存的事项摘要找回目标、停点和下一步；没有保存的聊天不会被当作长期记忆。你掌握自己的原始资料，也可以查看和修改整理后的文件。

可以直接编辑记录正文；行动日期和状态以 `scheduled_for`、`due_on`、`status` 元数据为准。只改正文中的日期，不会改变日程。可以交给 Agent 做局部调整；自己编辑时保留稳定 ID、合法 JSON 值和既有历史。

有些想法还不适合叫目标，可以先放在 `present/notes/`。一段工作、学习或求职告一段落时，可以保存一份 `present/stages/` 阶段回看，引用真实成果、记录选择的变化，再决定什么值得带到下一阶段。它不会自动替你结束项目或排下一轮任务。

新对话可以直接打开自己的工作区。里面会记录可验证的 Skill 位置；若之后移动了 Skill 包，让 Agent 按[定位修复说明](references/navigation.md)重新连接即可，不需要重建职业资料。

## 使用范围与当前进展

履迹复用已有 Agent 的对话、附件理解和工具能力，不附带独立模型服务。本地文件助手无需模型密钥；完整体验取决于宿主的文件读写、执行和展示能力。页面可在宿主支持的文件面板、对话或浏览器中查看，当前是带生成时间的本地快照。

简历提供六种排版，默认简洁双栏；照片可选，内容保留真实来源。你审阅确切的网页版本后，可用已安装的 Chrome/Chromium 导出同版 PDF。面试准备沿用同一份经历与成果，详见[简历流程](references/resume.md)和[面试流程](references/interview.md)。投递进展由你提供的实际事件更新，不自动发送简历或联系招聘方。

每次生成独立留版，PDF 的导出回执绑定确切版本和文件；没有可信回执的旧 PDF 或手工文件标为未核验。模板更新不让完好的历史 HTML 失效，职业来源是否变化另行说明。投递历史可以关联实际使用的简历文件；不确定时明确未记录，不推断为最新版。

README 提供简体中文、英文、日文、韩文和西班牙文。工作区首用指南与使用地图目前提供中文、英文两种，初始化选择 `zh` 或 `en`；可以用自己的语言与 Agent 交流，实际理解能力取决于宿主。底层目录名保持兼容，网页工作台的固定界面文案目前仍以中文为主，操作规范主要使用中文。这次 README 翻译不代表完整界面已完成多语言适配。

当前没有内置后台提醒或实时同步；通知和语音等能力依赖宿主。各宿主需要的能力、展示降级方式和实际验证范围见[宿主适配说明](references/hosts.md)。旧格式工作区保留，不自动迁移。测试与未覆盖项见 [TESTING.md](TESTING.md)。

试用材料均为虚构，个人职业资料不随源码分发。页面和工具来源见 [ASSETS.md](ASSETS.md)，项目采用 [MIT](LICENSE) 许可，允许商业使用。
