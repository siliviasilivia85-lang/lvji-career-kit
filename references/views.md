# 可视化：同一份文件的可重建视图

## 统一入口与实际面板

当前Skill的主工作台是一个生成的HTML文件，默认在个人工作区 `views/overview.html`。模板源码 `assets/md_workspace.html` 含数据占位符，需要生成后再打开；不是用户资料页面。四个一级视图共用同一份快照数据，在顶部标签切换：

| 标签 | view参数 | 实际内容与入口 |
| --- | --- | --- |
| 总览 | overview | 持续事项、今日行动、最近进展；折叠回看已完成/暂停事项、note、stage-summary和全部成长日志；“来路与当前理解”打开过往记录与来源 |
| 统一计划 | plan | 日行动列表、周7天日历、月42格日历、年12个月卡片；可切换日期/时段，点行动看详情 |
| 所向 | roles | 横向方向卡片；证据支持、资料充分度、个人偏好独立排序；详情进入公司/JD、思考、简历与面试材料 |
| 投递进展 | applications | 公司机会按实际阶段分列；方向/公司/机会/阶段筛选；单机会历史显示确切用版、反馈和下一步，未知/缺失不猜链接 |

“过去”没有独立一级HTML，入口在总览。“面试准备”没有独立一级面板，入口在方向/公司JD/机会详情。资料地图MAP及导航清单是Markdown，显示原件位置和处理状态，不是第五个HTML视图。

网页简历是独立留版的页面：岗位通用版位于 `future/roles/<方向>/common/resumes/<版本>/resume.html`，公司版位于 `future/roles/<方向>/companies/<公司>/<机会>/resumes/<版本>/resume.html`，可从详情的“已有简历版本”进入。六种排版为简介侧栏、证据档案、经典单栏、简洁文本、项目优先、经历优先；排版不是六套职业面板。生成与审核见[简历流程](resume.md)。

选择排版时，可由 `scripts/demo_gallery.py --output <新预览目录> --date YYYY-MM-DD` 生成单独的虚构样式画廊，入口是返回的index.html；六排版×头像A/B/无头像共18个预览，附7个GitHub参考外链。它是样式选择工具，不新增第五个职业面板，不读取或修改个人工作区。画廊源码为 `assets/resume_gallery.html`，头像来源与提示词见包内ASSETS。

画廊内嵌预览不放不能执行的打印工具栏；外框“打开完整预览 / 打印”进入保留打印功能的独立页面，iframe sandbox保持。内嵌与完整示例均为派生，不新增用户简历版本。

## 查看与修改的区别

角色/公司筛选只是显示条件，导出的HTML仍包含生成时的完整payload；不构成按岗位的数据隔离或脱敏。需要分享时另做范围明确的独立材料，不能把筛选后的同一快照当作只含该角色的文件。

页面内可筛选、排序、切换视图和查看详情；查看日期只改变所见时段。当前没有直接编辑正文/任务日期并保存、拖拽排期保存或自动更新投递状态。修改经Agent的具体草稿、确认和文件保存流程完成，再生成快照；用户也可自己修改Markdown后要求重新读取。网页的“请Agent调整”只复制请求，不执行保存或回写。

## 生成和展示

用户直接在Agent里说想看什么或调整哪件事；Agent按地图定位，不要求先去页面取指令。只问一项时可在对话给局部结果，需要整体时再展示页面。用户要求看页面时使用 `scripts/md_views.py --workspace <绝对路径> --date YYYY-MM-DD`，默认 `views/overview.html`。可用 `--view plan --period weekly` 直达周视图；period支持daily/weekly/monthly/yearly，view支持overview/plan/roles/applications。用 `--role/--company/--opportunity` 传稳定ID筛选投递节点。模板 `assets/md_workspace.html` 可编辑，无框架、CDN或远程字体。读取失败保留旧文件，不用空内容替换。

同一生成文件可以用hash定位，例如 `#view=plan&period=weekly&date=2026-10-27`、`#view=roles&sort=fit`、`#view=applications`。这只选择打开位置，不创建新计划或改变事实。日期、时区和最少读取范围仍按逐轮协议处理；同一行动的日期/状态在各尺度共用，无日期的行动不冒充已排程。周一为一周开始，各公司不必经过同一套线性投递节点。

从整体资料生成完整快照时说明读取范围；用户只授权单份文档时只给局部对话结果，不擅自扩展全库。页面保留workspace_id、生成时间、来源路径；不能把打开的旧页面当最新数据。比较/画像源变化的警告必须可见。

展示优先使用宿主实际支持的内联或文件面板；否则提供实际HTML入口。生成、打开、持久保存分别报告。限制阻止预览时不切换协议、端口或工具绕过。

现有页面“交给Agent调整”只复制含文件路径和请求的文本，是可选兼容入口；日常在Agent自然表达即可。网页没有后台保存；直接改正式Markdown后重新读取/生成。页面选中项自动传给对话、即时局部刷新需要宿主明确的事件/展示连接，当前纯Skill不保证。离线HTML要出工作区时注意包含职业资料，不当成可直接公开的宣传页。

工作区MAP/AGENT-MAP与页面用途不同：前者呈现目录、材料处理状态和检查范围，页面展示已整理记录。刷新清单不代表新原件已被理解或已进入页面；生成页面也不代表所有目录都检查过。两者失败与时间分别报告。

设计以任务为重：少字号层级、克制阴影、稳定文字，不持续漂移挡阅读。窄屏、键盘、减少动态偏好下保持等价操作。具体参数可改模板，不必改主数据或重新做产品。

视觉使用雾白毛玻璃、细边高光与统一圆角。筛选浮层/排序chips/阶段条件只影响本页展示，结果立即生效，动画可被新输入取消。hash可保留sort/stage和显式清空条件；宿主限制history时不影响当前筛选。复制请求只引用当前筛选的实际文件，空结果不扩大为全库。键盘/Escape/外点关闭和减少动态效果保持可用；无blur支持时用不透明降级。

面试材料沿现有岗位/公司机会/JD详情打开，通用故事与本机会各轮准备/模拟分开；卡片不展开长路径，正文支持安全的标题与段落排版，引用来源按需展开。历史节点可展开回看，准备入口不被长历史挤到页尾。修改或练习仍交给当前Agent，快照本身不运行模拟或写入。

## 维护者如何区分旧探索

在完整产品仓库中，`frontend/public/prototypes/` 下的纸面/宇宙等独立原型，以及对话可视化目录里的浮窗联动、功能地图、漫游探索，不作为当前Skill入口，也不随便携包交付。当前维护的看板模板只有包内 `assets/md_workspace.html`；简历排版维护在 `scripts/resume_layout.py`。旧文件保留，不用其页面数量或交互演示推断当前Skill已经具备的功能。
