# 面试准备：同一份证据，按岗位、公司与轮次展开

用户说“结合我的经历准备面试”“帮我练项目追问”“上次没答好，继续准备”时读取。简历和面试属于同一条应聘准备流程，复用原始经历与确认成果；面试材料是有来源的表达与练习，不是新增职业事实。

## 本轮先读什么

先按[Agent地图](agent-map.md)检查所选机会目录；新放的JD或反馈只在相关范围内发现、读取，不混入其他公司。通用讨论不要求已有role：没有档案时可先在对话准备，值得续接时保存独立事项摘要；需要正式岗位/公司轮次材料时才确认相应归档范围。

1. 沿用当前岗位与机会；不知道对象时用 `scripts/md_interview.py --workspace <工作区> context --role <ID>` 定位。公司版加 `--company <ID> --opportunity <ID>`，已知轮次可加 `--round <ID>`。`list` 用于找回已有材料。岗位context也列同岗公司/机会候选ID，不必另查全部future；选定公司后收窄。它们只列目标、候选来源和材料元信息，不等于读过正文，也不提供保存授权。
2. 按本轮问题显式读取目标或该公司JD、相关工作/项目、必要学历与技能、当前实际学习/工作产出。续接时再读选中的故事卡、上一版准备、相关演练或真实反馈；不把其他公司的全部材料混入。
3. 把输入分清：已确认经历和实际产出支撑个人陈述；学习记录可说明正在学习什么；未完成计划只说明准备方向。JD与公开研究用来决定问题和侧重，不能证明用户已会。画像、匹配判断和旧简历可辅助定位，个人事实仍追到原文件。
4. 列实际使用的 `relative_path` 和关键缺项。介绍本人时才取需要的个人信息，不默认带联系方式或照片。需要公司研究时只搜索公开公司/产品/职位信息，记录URL与日期，不把私人简历发作检索词。

可以先按岗位做通用准备，不强迫用户先选公司、提供面试日期或建立一整套档案。轮次未知时仍可讨论；要保存公司版时，先给用户看“待确认轮次”的具体归档草稿，Agent用稳定ID标识，后续确认后沿用ID。相对日期按用户时区换算；只在会改变方案时补问可用时间。

## 生成什么

结合 [准备提示词](../prompts/interview-prep.md)，按用户时间选择重点，不默认输出冗长题库。

| 产物 | 应包含什么 |
| --- | --- |
| 准备单 | 本轮岗位关注点、优先准备顺序、已有证据、仍需核实的内容；日期/可用时间未知就明确保留 |
| 经历故事卡 | 适用问题、背景与本人职责、关键选择及理由、实际行动与结果、困难/反思、可能追问；个人陈述逐段对应来源 |
| 岗位问题与回答提纲 | 问题为何与此JD有关、可用故事/成果、回答结构、可能追问与缺项；预测的问题标为推演，不冒充公司真实题目 |
| 反问与模拟面试 | 反问团队/产品/岗位的问题；模拟时一次问一个，依据用户实际回答追问，再给有依据的表达建议 |

时间紧时优先完成自我介绍、最相关的两三个故事、关键缺口与反问；不因压缩省略缺失标记。没有证据时给“需要补充什么/如何练习”，不替用户编一段成熟答案。正在学习可以诚实表达，但不能写成已有生产经验或量化成绩。

## 留在哪里

```text
future/roles/<方向>/
  common/interviews/
    stories/<故事>.md                  interview-story：可复用的真实经历表达
    prep-<版本>.md                     interview-prep：岗位通用准备
    practice-<日期>-<标识>.md           interview-practice：岗位通用模拟记录
  companies/<公司>/<机会>/
    interviews/<轮次ID>/
      prep-<版本>.md                   interview-prep：本公司、本轮准备
      practice-<日期>-<标识>.md         interview-practice：本轮模拟记录
    feedback/<日期>-<标识>.md           feedback：真实面试/招聘方反馈
```

目录按现有目标和机会定位，不复制一份新的JD。岗位共性故事在通用目录复用；公司准备引用它，并补本公司JD、轮次侧重及相关反馈。公司专属判断不塞进通用故事。字段、命令与生成示例见 [文件契约](workspace.md)。

先展示具体草稿、来源、缺失和拟保存路径，再按逐轮协议提案/确认/保存/回读；有新原件整理关联时核实后刷新地图。准备稿用独立版本；已用稿不改写。演练记录引用当时的准备稿，后续新准备稿可以引用这次演练；不要反向改旧准备稿的来源造成引用环。修改可复用故事时保留旧故事与准备稿的来源关系，基准变化须重新核对，不为消警告只换哈希。

`interview-practice` 保存用户实际模拟回答、追问、反馈和未解决点；不用AI代答冒充用户回答。真实面试复盘与招聘方反馈沿用 `feedback`，可记录 `round_id`，区分“用户回忆”“招聘方原话”“Agent分析”。准备或模拟不会自动将application改成面试阶段。真实事件要更新投递节点时，另展示并确认相应事件草稿。

## 下一轮怎么继续

- 表达缺口：优先改故事组织或回答提纲，新版保留原事实。
- 实践/知识缺口：提出最小可验证的练习或作品；用户采纳后走 [此刻成长](present.md)，不因面试建议自动排进日程。
- 新增真实经历/成果：先形成源事实或成果确认草稿，保存后再引用；模拟得分、流畅回答和预测问题不能沉淀为工作业绩。

岗位/机会详情可以查看已保存材料、轮次和来源；需要练习或修改时回到Agent。文件已保存、快照已生成、页面已打开分别报告。工具能检查结构与来源是否变动，不能保证答案真实、面试官必问或录用结果。
