# 逐轮：先解决问题，再选择读取与产物

## 先定位本轮

沿用已确认的工作区绝对路径、workspace_id、时区、对象与用户授权。同一对话启用后不用逐轮重复指令；切换事项只改变当前焦点，无关问题直接回答。“结合我”“继续上次”“本周安排”才需要本地背景；模糊想法可以先讨论，不为目录字段强制建目标。

读取顺序是工作区 `AGENT-MAP.md` → 所选范围清单 → 对象摘要 → 必要正文/引用。按[导航协议](navigation.md)检查相关目录变化；已知对象且本轮无发现新材料需要时，可直接显式读取。未知对象先用清单或范围内 `index --area ... --type ...` 定位。索引不是全文，原件哈希不是内容理解；列实际用到的相对路径。缓存不能作正式写入基准。

| 请求 | 最少读取 | 产物与完成判断 |
| --- | --- | --- |
| 整理过去/新放材料 | 指定入口范围清单 → 选中的新原件 + 确有重复的旧记录 | 原件保留、真实提取草稿、缺失项；确认后独立MD与整理关联 |
| 继续一个项目 | 所选item摘要 + 有关action + 最新相关log；相关materials有变化才补读 | 找回目标、停点、已定/未定、下一步；不读其他项目全文 |
| 探索一个想法 | 本轮对话；用户选的引用 | 阶段小结，可仅留记录；不自动创建方向 |
| 只存想法 | 本轮结果；同一note的现有版本（若有） | present/notes的note具体草稿；无目标/事项也有效 |
| 阶段回看/离职/Offer/入职/转向 | 选定时间与事项范围、既有摘要、实际日志/产出/反馈 | 按[阶段承接](stages.md)给stage-summary；后续行动与状态另作具体变更 |
| 看已有计划 | 明确日期范围的plan和action | 原有安排与状态；查看不重排 |
| 规划一周 | 已采纳item、未完成action/依赖、相关目标、可用时间 | 具体成果、容量、冲突、未排项；先给草稿 |
| 目标适配 | goal/具体JD + 相关经历与已确认成果 | 分要求判断、证据/未知/差距；目标可无JD |
| 准备面试/模拟/复盘 | 目标或本公司JD + 相关经历/实际成果；按需续接故事、该轮准备与反馈 | 按[面试流程](interview.md)给准备草稿或逐题模拟；实际回答与建议分开，不自动改阶段/排任务 |
| 更新投递阶段 | 该机会application/JD + 用户反馈；已知实际用版时读取准确artifact binding | 真实事件、resume_ref与下一步草稿；未知不猜，保留事件历史 |
| 调整一项 | 目标完整MD + 受影响直接依赖 | 最小差异；不顺手重排所有内容 |
| 看页面 | 相应已存文件；总览经说明读取展示所需范围 | 实际快照、时间、展示状态 |

日期用用户时区，周一至周日；“周五”转明确日期。未确定时长、预算、截止标未知，只有会实质改变方案时才问。不能因局部未读就下“你没有其他经验”的全局结论。

## 自然语言触发与适时引导

启用Skill后，由Agent结合本轮意图、相关文件状态和讨论进度选择工作流，文件助手负责读取、版本和保存校验；用户不需要触发口令。中文、英文及混合表达按同一语义判断，用用户当前语言回应。提到岗位的词本身不构成建档授权，否定、假设、引用别人和历史愿望都应按原意处理。

| 识别到的意图/状态 | 下一步 | 留存边界 |
| --- | --- | --- |
| 开始职业规划，尚无过往材料 | 先按用户已说明的愿望和现实条件给起步方案；相关基础标待了解 | 不要求先上传简历或完成画像，不把未提供当没有能力 |
| 附材料说“这是我的简历”等，语境是建档/资料收录 | 按past工作流接收原件、定位已有版本并提取草稿；仅点评的请求先点评 | 指定原件收录与经历事实确认分开；不以最近上传推断最新使用版 |
| 了解/比较一个职业，如“我想了解产品经理” | 讨论职责、选择与待验证问题 | 不仅因提及岗位就询问建档；没有保存请求也能继续 |
| 表达可能去向，如“我想做产品经理” | 先承接讨论，在形成可保留结果的自然停顿给候选方向草稿 | 新候选默认exploring；已有方向保留采纳状态，除非用户改变决定。显示已知内容和待定项，再询问是否保存 |
| 明确决定发展某方向 | 展示adopted方向草稿，已有同一方向则提出局部更新 | 对具体草稿确认后保存；不连带采纳全部建议或排满日程 |
| 只想做一个项目/学一项技能 | 拆成独立此刻事项、可判断产出与下一步 | 无过去、无未来方向也可成立；行动与方向的关联可为空 |
| 已有方向，想拆解近期推进 | 方向→中期里程碑→短期行动；按可投入时间取舍 | 行动和计划按同一批具体草稿确认；不会因存了方向就自动排期 |
| 补充了材料、进展或想法变化 | 定位受影响的既有事项/方向，给必要差异 | 不重复建同名对象，不自动改其他承诺；完成记录不自动成为能力证据 |

来路是已发生的积累，此刻是正在探索或推进的事项与行动，所向是希望达到的状态；用途优先于长短期标签。六个月的作品项目仍可在此刻，近期开启的职业方向也可在所向。目标还未实现时不写成过往经历；同一项目可关联多个方向，也可不关联。

### 缺资料怎样提醒

先判断缺失是否会改变当前方案。例如做起步规划时，已有相关实践和每周可投入时间比完整学历、照片或获奖更有用；不要发送全档案补齐清单。优先问影响最大的少量信息，其余合并为一次可选提示，允许跳过并给有边界的起步草稿。时间未知可以拆成果，具体日期/容量标待定，不编造排程。

区分“尚未提供”“用户明确说没有”“暂时不补/不愿提供”“文件读失败”。后两类分别尊重选择或报告错误，不能都当作空资料。用户说“先不补”后，本轮及当前对话不再机械追问；有新任务确实需要时，说明影响并提供不依赖该资料的替代路径。用户主动重开、约定的相关节点到来或任务条件改变，才重新评估是否需要提醒。

跨对话续接时，将确有需要的“待了解内容、为什么需要、用户选择、何时再看”合入同一事项的具体摘要草稿，确认后保存在正文；不增加必填schema或复制一套职业档案。没有实际保存的偏好不假称已经记住。缺失状态随新资料重新核对，已补的不再提示。对话内提示无需通知服务；离开对话后的定时通知只在用户明确要求且宿主支持时另行设置，本Skill不启动后台监听。

### 一次清楚的确认

在讨论已形成结果或准备暂停时，合并展示本次拟保留的方向、事项/行动与待补内容，清楚标明探索/已采纳、写入位置和未定项；只建议与本轮有关的选择。用户可只保存事项、只留方向，或继续讨论。紧接具体草稿且明确指向该版的自然表达可构成确认，不要求固定口令，不再叠加“是否建档/是否保存”多次询问；单独的“继续”、模糊赞同或仅同意方法不自动授权写入未展示内容。

不把“愿望→方向→行动”做成每次必经的问卷。查看已有内容、普通小问题和已经说明不保存的讨论直接完成本轮即可；同一方向先定位再更新。保存仍按下节context/propose/apply/回读执行。

## 生成和保存

讨论的新事实、建议先留在对话。用户口述过往经历时，关键词只帮助识别可能值得保存的内容；在有值得留存的变化或暂停前合并提出具体摘要，不每句话打断。浏览、读取、分析无需保存确认；正式修改、采纳和沉淀才走以下流程。

1. 选一个有意义的颗粒度：一段工作、一个项目、一个学习主题、一次目标决策。保留发生时间与本次记录时间。不是一句话一个文件。
2. 展示具体草稿/差异、来源、未确认判断和计划改哪些文件。用户已看过这版并确认就沿用，不要求固定口令。
3. 把所有将改文件和新草稿实际用到的来源一次 `context --path ...`，工具自动补它们声明的递归来源，取同一份 `draft_base`。内容变化必须更新草稿；不能只替换哈希绕过冲突。
4. `propose` 只写待确认提案。`apply --confirmed` 仅在该版已有确认时使用；具体字段见 [workspace.md](workspace.md)。工具不能验证人类的真实意愿，Agent承担这条交互责任。
5. 保存后回读改动文件，核对未要求字段与来源。新原件形成正式记录时按导航 `link` 核实关联，再刷新相关范围双地图。按需刷新页面，不每个回答都生成HTML。

一批相关变更可合成一个清晰草稿一次确认。保存探索不等于采纳目标；确认任务完成不等于确认能力；确认简历措辞不等于改写源经历。

跨小对话只读已保存item摘要和用户指定引用。摘要保留：目标/议题、已决定、未确定、当前停点、下一步、来源、记录日期、待采纳草稿，以及哪些仍是推断。未保存草稿与已采纳安排分开；没有留存的聊天不假称记忆。新对话先从地图定位同一事项，不能拿最新文件名代替用户指定对象。

## 直接投放与直接编辑

用户已经放入资料入口的原件，不再要求复制归档指令或重复确认保留原件；不自动移动、改名或写入事实。先按本轮需要理解内容，能够只读分析就先回答。要更新正式记录时再给具体草稿。目录检查只覆盖所选范围，未检查区域与旧时间要保留，不能声称全库最新。

用户直接编辑正式Markdown后，下一次读取使用实际文件并检查相关派生结论。Agent代写仍取得具体确认与最新来源基准；不因已有导航缓存而跳过 `context`。指南和目录清单不作为能力证据。

## 失败与续接

- 路径不存在/读不清：说明具体文件及影响，保留可靠部分，不伪装成空工作区。
- stale/来源变了：保留提案，重读并比较；展示变更后再确认，不覆盖别人修改。
- apply中断：用同一proposal查询/重试恢复；报告实际已写范围，不能另建重复事实或删活锁。
- 资料保存成功而页面失败：明确分别说明；旧快照保留原时间。
- 导航检查失败：说明范围，保留旧清单/地图与其时间；不得改成空库或把未发现当没有。
- 页面已生成但没打开：给实际入口，按宿主能力展示。安全策略拒绝时不换途径绕过。
- 未知/旧格式：不写入，解释应使用原工具或新的空目录；不无声迁移。
