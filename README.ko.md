## LüJi를 만드는 이유

다음 커리어를 진지하게 고민하기 시작했을 때는, 이미 지금 하는 일에서 더 성장하기 어렵다고 느끼는 경우가 많습니다.

그제야 예전 프로젝트를 찾고, 이력서를 고치고, 어떤 방향으로 갈지 생각합니다. 해 온 일도 배운 것도 적지 않지만 기록이 흩어져 있어, 그 경험이 무엇으로 쌓였는지 설명하기는 쉽지 않습니다. 여러 직무를 알아보려면 이력서도 각각 준비해야 합니다. 다음 걸음을 충분히 생각하기도 전에, 취업 자체가 목적이 된 채 서둘러 움직이게 됩니다.

하지만 역량이 쌓이는 데는 시간이 필요합니다. 이력서는 며칠 만에 고칠 수 있어도, 깊이 있는 실무 경험과 다른 일에도 이어 쓸 수 있는 능력은 일상 속에서 조금씩 만들어집니다. AI가 직무의 경계와 요구를 바꾸는 지금, 커리어 준비도 변화가 닥친 뒤가 아니라 평소의 일과 생활 안에서 시작되어야 합니다.

**LüJi는 성장으로 이어지는 커리어의 흐름을 함께 정리합니다. 과거의 경험을 다시 찾아보고, 미래의 가능성을 지금 할 일로 옮기며, 오늘의 노력이 다음 선택의 밑거름이 되도록 돕습니다.**

이미 사용하는 Agent에 사고의 틀과 로컬 파일 도구, 시각화 스냅샷을 더해 나만의 커리어 조언자로 활용할 수 있게 합니다. 경험을 정리하고, 행동을 나누고, 결과를 돌아보며 기회를 살펴보는 과정이 읽고 고칠 수 있는 파일로 남습니다. 흩어진 준비를 오래 이어 갈 수 있는 성장의 과정으로 만드는 것이 이 도구의 목적입니다.

이 문서는 한국어 README입니다. Agent와는 한국어로 대화할 수 있지만, 자동 생성되는 작업공간 안내와 지도는 현재 중국어 또는 영어(`zh` / `en`)를 선택해 사용합니다. 작업 화면의 고정 문구와 Agent용 상세 지침도 대부분 중국어입니다. README 번역이 제품 전체의 한국어화를 뜻하지는 않습니다.

## 과거, 현재, 미래를 연결합니다

### 과거: 지나온 경험에서 성장의 단서를 찾습니다

그동안의 업무, 프로젝트, 학습 과정과 경험은 잘 보관하고 때때로 돌아볼 가치가 있습니다. LüJi는 자료를 주제별로 정리하고 원본과 출처를 남기며, 나중에 떠오른 세부 내용도 보충할 수 있게 합니다. Agent와 함께 경험, 선호, 다른 분야로 이어 갈 수 있는 역량을 살펴볼 수 있습니다. 물론 다음 선택이 과거와 다른 길을 향해도 괜찮습니다.

### 현재: 긴 안목의 방향을 실제 일주일 안에 놓습니다

성장 계획은 실제 생활에 들어갈 수 있어야 합니다. 당장 해야 할 일이 있고, 한 주에 쓸 수 있는 시간은 제한되어 있으며, 예상하지 못한 일로 계획이 달라지기도 합니다. LüJi는 지금의 상황과 여유 시간을 바탕으로 생각을 프로젝트, 단계별 결과물, 일·주·월 단위의 행동으로 나눕니다. 진행이 어렵다면 한 걸음을 줄이거나 속도를 바꾸고, 무엇을 계속할지 다시 선택할 수 있습니다.

### 미래: 여러 가능성이 같은 경험 위에서 자라게 합니다

미래의 방향은 하나일 필요가 없습니다. 서로 다른 직무가 요구하는 능력에도 공통점이 있습니다. 하나의 프로젝트, 학습, 실무 경험이 여러 가능성을 함께 준비하는 기반이 될 수 있습니다. 목표마다 처음부터 다시 시작하기보다, 목표의 요구를 현재 쌓을 수 있는 역량과 행동으로 연결합니다.

실제로 구직을 시작할 때는 과거와 현재의 축적에서 필요한 내용을 골라 직무별·회사별 이력서를 만들고 관리합니다. 면접을 준비하고, 지원 진행 상황과 대화 경험, 피드백을 기록합니다. 그렇게 얻은 피드백은 방향을 다시 생각하고 지금의 행동을 조정하는 근거가 됩니다.

근거가 충분한 부분과 아직 알 수 없는 부분도 구분합니다. 자료가 부족하다는 이유만으로 역량이 부족하다고 판단하지 않습니다. 근거의 뒷받침 정도, 정보의 충실도, 개인의 선호는 따로 살펴봅니다.

이 흐름에는 실제 근거가 필요합니다. 일을 마쳤다는 사실은 먼저 진행 기록으로 남길 수 있습니다. 작품, 실제 산출물, 피드백을 함께 확인한 뒤에야 어떤 역량을 뒷받침하는지 말할 수 있습니다. **실천이 경험을 남기고, 선택이 새로운 이해를 가져올 때 커리어는 하나의 흐름으로 이어집니다.**

연결은 조금씩 만들어도 됩니다. 목표를 만들지 않고 탐색하거나, 프로젝트를 시작하지 않고 생각만 저장하거나, 다음 단계를 정하지 않은 채 한 시기를 마무리할 수도 있습니다. 중요한 내용은 먼저 구체적인 초안으로 제시하며, 검토하고 저장할지는 사용자가 결정합니다.

## 시작하기: 익숙한 경험 하나부터 정리합니다

직접 해 본 프로젝트, 한동안 맡았던 업무, 하나의 학습 경험을 골라 보세요. 예전 이력서의 일부, 프로젝트 회고, 학습 노트면 충분합니다. 문서가 없다면 있었던 일을 적어도 됩니다. 처음부터 완전한 경력 자료를 준비할 필요는 없습니다.

과거 자료가 아직 없다면 지금 탐색하고 싶은 일부터 이야기해도 됩니다. 경험은 나중에 보충할 수 있고, 아직 결정하지 않은 생각만 따로 남길 수도 있습니다.

1. **개인 작업공간을 만듭니다.** 내려받은 패키지를 평소 사용하는 Agent에서 열거나 접근을 허용합니다. 루트의 `AGENTS.md`와 `SKILL.md`를 읽고 개인 작업공간과 자료 지도를 만들어 달라고 요청하세요. 안내 언어는 현재 중국어 또는 영어 중에서 선택합니다. 중국어 시작 파일은 `从这里开始.md`, 영어는 `START-HERE.md`입니다. 처음 한 번 설정한 뒤에는 평소처럼 대화하면 됩니다. 전체 파일 작업에는 로컬 파일 읽기·쓰기·실행 권한과 Python 3.10+가 필요합니다.
2. **그 경험의 자료를 넣습니다.** 작업공간의 `past/materials/`에 넣고, 분류가 애매하면 `inbox/`를 사용합니다. 첨부파일을 Agent에 주고 가져와 정리해 달라고 할 수도 있습니다. 직접 넣은 원본은 이름과 위치를 유지합니다. 일반 메모, PDF, Word 문서, 이미지에 내부 필드를 작성할 필요는 없습니다. 첨부파일을 정확히 이해할 수 있는지는 사용하는 Agent에 따라 달라집니다.
3. **함께 정리하고 확인합니다.** Agent가 무엇을 했고, 어떤 역할을 맡았으며, 무엇을 남겼는지 출처와 불확실한 부분을 포함해 초안으로 정리합니다. 빠진 내용을 보충하고 잘못 이해한 부분을 고친 뒤, 그 초안을 승인하면 읽을 수 있는 Markdown 기록으로 저장됩니다. 원본은 그대로 남습니다. 기록 본문은 직접 고칠 수도 있으며, 작업 날짜와 상태는 별도 필드를 사용하므로 Agent에 조정을 맡기는 편이 간단합니다.
4. **작업 화면에서 결과를 살펴봅니다.** Agent에 작업 화면을 생성해 보여 달라고 요청합니다. 개요의 과거 기록 영역에서 방금 정리한 기록과 출처를 열어 봅니다. 현재 중국어 화면에서는 “总览 → 来路与当前理解”에 해당합니다. 부정확한 부분은 Agent에 수정을 요청하거나 Markdown을 직접 고친 뒤 화면을 다시 생성합니다. 웹페이지는 현재 조회와 선택을 위한 것이며, 페이지 안에서 수정 내용을 직접 저장하지는 않습니다.
5. **이 경험에서 다음 걸음을 이어 봅니다.** 지금 하고 싶은 일과 쓸 수 있는 시간을 바탕으로 진행할 만한 프로젝트나 행동을 논의합니다. 미래 방향과 연결해도 되고 독립적으로 진행해도 됩니다. 저장을 결정한 행동은 통합 계획에서 확인할 수 있습니다.

첫 정리가 끝나면 원본이 어디에 있는지, 저장된 기록이 무엇을 말하는지, 어떻게 바로잡을 수 있는지 알 수 있어야 합니다. 다음 대화를 어디서 이어 갈지도 분명해집니다. 가상 자료로 먼저 익혀 보고 싶다면 Agent에 [체험 안내](examples/try-it.md)를 따라 새 임시 폴더에서 진행해 달라고 요청하세요.

## 일상 자료는 어디에 넣나요?

아래 경로는 모두 개인 커리어 작업공간 안의 경로입니다. 새로 시작할 때는 Skill 설치 폴더 밖의 `~/lvji-workspace/`를 권장합니다. 기존 작업공간은 확인된 경로를 유지하며 자동으로 옮기지 않습니다.

| 자료 | 넣을 위치 |
| --- | --- |
| 예전 이력서, 증명서, 과거 업무·프로젝트 자료, 학습 노트 | `past/materials/`; 주제별 하위 폴더를 만들어도 됩니다 |
| 현재 공통으로 사용하는 자료 | `present/materials/` |
| 진행 중인 특정 프로젝트의 자료 | `present/items/<item>/materials/` |
| 아직 소속을 정하지 않은 방향 조사나 JD(채용 공고의 직무 설명) | `future/materials/` |
| 특정 방향이나 회사의 채용 기회에 관한 JD, 스크린샷, 피드백 | 해당 방향 또는 기회의 `materials/` 폴더 |
| 아직 어떻게 분류할지 모르는 자료 | `inbox/` |

`MAP.md`는 사용자가 실제 파일을 찾는 자료 지도이고, `AGENT-MAP.md`는 Agent가 이번 작업에 필요한 내용만 찾도록 돕는 지도입니다. 두 지도는 같은 목록에서 생성됩니다. 파일을 직접 넣어 두면 Agent가 다음 관련 요청을 처리할 때 그 범위의 변화를 확인하고, 필요한 내용을 읽은 뒤 정리 결과를 함께 검토합니다. 파일을 발견하는 것, 내용을 이해하는 것, 경험의 사실관계를 확인하는 것은 서로 다른 단계입니다.

시작 안내, 분류별 설명과 지도는 현재 중국어 또는 영어로 생성됩니다. 실제 디렉터리 이름은 `past/`, `present/`, `future/`로 유지되어 언어나 Agent를 바꿔도 기존 참조가 끊기지 않습니다. 직접 만드는 파일 이름과 주제별 폴더에는 한국어를 사용할 수 있습니다. 자료 폴더 안에 사용자가 넣은 `README.md`도 일반 자료로 발견하며, 도구가 생성한 것으로 확인된 안내 파일만 제외합니다.

## 하나의 작업 화면, 네 가지 보기

**주 작업 화면은 개인 작업공간의 `views/overview.html`에 생성됩니다.** 하나의 웹페이지에서 상단 탭으로 네 가지 보기를 전환합니다. 아래 중국어 이름은 현재 화면에 표시되는 이름입니다.

| 보기 | 확인할 수 있는 내용 |
| --- | --- |
| 개요（总览） | 진행 중인 항목, 오늘의 행동, 최근 업무·학습 기록, 펼쳐 볼 수 있는 완료·일시 중지 항목, 저장한 생각과 단계별 회고 |
| 통합 계획（统一计划） | 같은 행동 기록을 사용하는 일별 목록, 주간 달력, 월간 달력, 연간 개요와 계획 설명 |
| 방향（所向） | 가로로 배열된 커리어 방향, 근거의 뒷받침 정도·정보 충실도·개인 우선순위에 따른 별도 정렬, 회사별 JD·이력서·면접 자료 |
| 지원 현황（投递进展） | 실제 진행 단계, 다음 할 일, 이벤트 이력, 피드백, 기록된 경우 실제 사용한 이력서 버전; 방향·회사·채용 기회·단계별 필터 |

과거 기록은 개요 안에서 펼쳐 보며, 별도의 “과거” 최상위 웹페이지는 없습니다. 원본 자료와 정리 상태는 `MAP.md`에서 찾습니다. 면접 자료는 방향 또는 채용 기회의 상세 화면 안에 있습니다. 이력서는 버전별로 따로 저장되는 HTML 파일이며, 여섯 가지 레이아웃이 여섯 개의 작업 화면을 뜻하지는 않습니다.

페이지 안에서 필터링, 정렬, 상세 조회를 할 수 있습니다. 본문, 작업 날짜, 지원 상태를 바꾸려면 Agent에 변경할 부분을 말하고 구체적인 차이를 검토·승인한 뒤 저장하고 스냅샷을 다시 생성합니다. 한 작업을 수정했다고 나머지 일정을 자동으로 재배치하지는 않습니다. Markdown을 직접 고친 뒤 다시 생성해도 됩니다. 화면의 “请 Agent 调整”는 요청 문구를 복사하는 보조 기능입니다. 일상적으로 지시문을 복사할 필요는 없습니다. 현재 웹페이지에는 직접 저장하거나 드래그해서 일정을 저장하는 기능이 없습니다.

**필터는 표시만 바꾸며 파일에 포함된 자료를 줄이지 않습니다.** 전체 스냅샷에는 생성 시 읽어 온 커리어 자료가 들어 있을 수 있습니다. 특정 직무로 필터링한 페이지를 그 직무의 자료만 담긴 공유 파일로 생각해서는 안 됩니다. 외부에 공유하려면 포함할 범위를 정한 별도 자료를 만드세요.

진입 위치, 생성 방식과 지원 동작은 [시각화 안내](references/views.md)에 정리되어 있습니다. `assets/md_workspace.html`은 자료를 넣어 생성하는 템플릿 소스이며, 그 파일을 바로 열어 개인 자료를 찾을 필요는 없습니다. 작업 화면의 고정 문구는 현재 주로 중국어입니다. Agent의 답변과 작성하는 기록은 한국어로 사용할 수 있습니다.

## 이력서와 면접 준비

특정 직무나 회사를 위한 이력서를 요청하면 Agent가 실제 경험과 확인된 결과물을 골라 사용합니다. 개인 정보, 소개, 업무, 프로젝트, 학력, 기술을 구분해 초안을 만들고 출처를 남깁니다. JD의 요구 사항이나 모의 면접 답변을 실제 경험으로 바꾸어 쓰지 않습니다. 일부 문단을 고쳐 달라고 하면 해당 부분을 중심으로 조정합니다.

여섯 가지 내장 레이아웃이 있습니다. 기본은 간결한 2단형이며, 소개 사이드바형·기본 1단형·근거 중심형·간결한 텍스트형·프로젝트 우선형·경력 우선형을 비교할 수 있습니다. 별도의 가상 샘플 갤러리에서 같은 경험을 여섯 가지로 보고, AI가 생성한 가상 인물 사진 A·B 또는 사진 없음을 선택할 수 있습니다. 실제 이력서에는 사용자가 지정한 사진을 사용하거나 사진을 넣지 않습니다. 가상 인물 사진은 가상 예시라고 명시된 시연에만 사용합니다.

갤러리는 GitHub의 외부 이력서 참고 프로젝트 7개와 공식 예시·라이선스 링크도 제공합니다. 외부 링크는 설치된 템플릿과 구분되며, 선택했다고 바로 내장 기능으로 사용할 수 있는 것은 아닙니다. 스타일을 고른 뒤에는 Agent에 이름을 알려 주고 자신의 자료와 사진으로 별도 이력서를 만듭니다.

이력서를 생성할 때마다 독립된 버전을 남깁니다. **그 HTML을 직접 검토하고 해당 버전을 승인한 뒤**, 이미 설치된 Chrome/Chromium으로 같은 버전의 PDF를 내보낼 수 있습니다. 내보내기 검증 기록으로 PDF의 무결성을 확인합니다. 검증 기록이 없는 예전 PDF나 수동으로 넣은 PDF는 검증되지 않은 상태로 표시합니다. 렌더러를 업그레이드했다고 변경되지 않은 과거 HTML이 무효가 되지는 않습니다. 경력 자료가 이후 달라졌는지는 따로 알려 주므로, 온전히 보존된 과거 버전과 새 검토가 필요한 현재 초안을 구분할 수 있습니다.

직무 공통 이력서는 `future/roles/<role>/common/resumes/<version>/`, 회사별 이력서는 해당 채용 기회의 `resumes/<version>/` 아래에 저장됩니다. 꺾쇠 부분은 실제 방향과 버전 이름을 나타내는 예시입니다. 지원 이벤트에는 실제 사용한 정확한 파일을 연결할 수 있습니다. 모르는 경우는 “기록되지 않음”으로 남기며, 가장 최근 버전을 보냈다고 추정하지 않습니다. 수정된 새 버전이 과거에 제출한 버전을 덮어쓰지 않습니다.

면접용 경험 이야기, 회사별·차수별 준비, 연습, 실제 피드백은 같은 경험과 근거를 바탕으로 이어집니다. Agent는 지원서를 자동 제출하거나 채용 담당자에게 연락하지 않습니다. 상세 절차는 [이력서](references/resume.md)와 [면접](references/interview.md) 안내에 있습니다. 현재 이 운영 지침은 중국어이며, Agent가 이를 따라 사용자의 언어로 응답합니다.

## 가상 데모 살펴보기

스크린샷은 가상임을 명시한 대화 예시입니다. 경험 정리, 방향 탐색, 실행 가능한 행동, 기록의 축적을 연결하고 그 결과로 계획·지원 기회·이력서를 보여 줍니다. 데모 웹페이지는 온라인 Agent를 실행하거나 방문자의 자료를 저장하지 않습니다.

관리자는 정적 사이트를 생성할 수 있습니다.

```text
python3 scripts/demo_site.py --output _site
```

출력 폴더는 새 폴더여야 합니다. 가상의 읽기 전용 페이지와 로컬 자료만 내보내며, 컴퓨터 경로·개인 작업공간·실행 이력은 포함하지 않습니다. 저장소를 만든 뒤 Pages의 게시 원본을 GitHub Actions로 정하고 [데모 게시 워크플로](.github/workflows/pages.yml)를 수동 실행할 수 있습니다. 저장소 전체나 개인 자료 대신 `_site/`만 게시합니다. 워크플로가 준비되었다고 온라인 사이트가 이미 공개된 것은 아닙니다.

## 다시 돌아올 수 있는 기록을 남깁니다

```text
lvji-career-kit/               내려받은 Skill 패키지
├── README.md / README.en.md   중국어·영어 사용자 안내
├── README.ja.md / README.es.md   일본어·스페인어 사용자 안내
├── README.ko.md              한국어 사용자 안내
├── SKILL.md / AGENTS.md       Agent 진입점
├── references/                작업별 절차
├── prompts/                   커리어 해석, 격차 분석, 면접, 회고 지침
├── scripts/                   로컬 표준 라이브러리 도구
├── assets/                    수정 가능한 화면 템플릿과 가상 사진
└── examples/                  소량의 가상 원본 자료

~/lvji-workspace/             Skill 설치 폴더와 분리한 개인 자료; 배포에 포함되지 않음
├── START-HERE.md          영어 시작 안내; 중국어: 从这里开始.md
├── MAP.md / AGENT-MAP.md  같은 목록을 사용하는 두 지도
├── inbox/                 미분류 원본
├── past/                  과거 경험과 학습
├── present/               진행 항목, 행동, 계획, 로그, 생각, 단계별 회고
├── future/roles/          방향 → 회사 → 채용 기회
├── views/overview.html    다시 생성할 수 있는 작업 화면
└── .luji/                 초안, 이력, 파생 탐색 설정
```

하나의 경험과 행동은 각각 하나의 주 파일에 저장되고, 여러 방향과 일·주·월 계획이 같은 기록을 참조합니다. 아직 목표라고 부르기 어려운 생각은 `present/notes/`에 따로 남길 수 있습니다. 업무, 학습, 구직의 한 단계가 끝나면 `present/stages/`에 회고를 남겨 실제 결과와 바뀐 판단을 돌아보고 다음 단계로 무엇을 가져갈지 결정할 수 있습니다. 원래 기록은 옮기거나 복제하지 않고 참조합니다. 회고를 저장했다고 프로젝트를 자동 종료하거나 다음 일정을 만들지는 않습니다.

새 대화에서는 개인 작업공간을 열면 됩니다. 진입 파일에 Skill과 저장된 문맥을 찾을 수 있는 위치가 들어 있습니다. 패키지를 옮겼다면 [탐색 설정 절차](references/navigation.md)에 따라 Agent에 다시 연결해 달라고 하세요. 작업공간의 식별자와 경력 자료를 새로 만들 필요는 없습니다. Agent는 저장된 요약에서 목표, 멈춘 지점, 다음 걸음을 찾아 이어 갑니다. 저장하지 않은 대화를 장기 기억처럼 취급하지 않습니다.

기록 본문은 직접 편집할 수 있습니다. 일정의 날짜와 상태는 행동의 메타데이터인 `scheduled_for`, `due_on`, `status`를 사용합니다. 본문에 적힌 날짜만 바꾸어서는 일정이 바뀌지 않습니다. Agent에 해당 부분을 조정해 달라고 하거나, 직접 편집할 때는 ID와 JSON 값, 기존 이력을 유지하세요.

## 실행 조건과 현재 범위

로컬 도구에는 Python 3.10+가 필요하며, 모델 키나 별도의 Python 패키지는 필요하지 않습니다. 대화와 첨부파일 이해는 기존 Agent의 기능을 사용합니다. **자료를 로컬에 보관한다고 Agent의 모델까지 오프라인으로 동작하는 것은 아닙니다.** 실제 사용 범위는 해당 환경의 파일 읽기·쓰기·실행·표시 기능에 따라 달라집니다. 스냅샷은 지원되는 대화 내 미리보기, 파일 패널 또는 일반 브라우저에서 볼 수 있습니다.

백그라운드 알림, 상시 감시, 실시간 화면 동기화는 내장되어 있지 않습니다. 음성이나 알림 기능은 사용하는 Agent 환경에 따라 달라집니다. 기존 형식의 작업공간은 그대로 보존하며 자동으로 이전하지 않습니다. 필요한 기능과 대체 경로는 [호스트 환경 안내](references/hosts.md), 실제 검증과 미검증 범위는 [TESTING.md](TESTING.md)에 있습니다. 모든 Agent와 운영체제에서 검증을 마친 것은 아닙니다.

현재 제공되는 작업공간 안내와 지도는 중국어·영어입니다. 이 한국어 README는 사용 방법을 이해하기 위한 번역이며, 한국어 UI나 한국어 작업공간 안내 생성이 구현되었다는 뜻은 아닙니다.

모든 예시는 가상입니다. 개인 작업공간과 실행 이력은 공개 소스 배포에 포함되지 않습니다. 화면과 도구의 출처는 [ASSETS.md](ASSETS.md), 라이선스는 상업적 사용을 허용하는 [MIT](LICENSE)를 참고하세요.
