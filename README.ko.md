# 履迹 LüJi

[简体中文](README.md) · [English](README.en.md) · [日本語](README.ja.md) · 한국어 · [Español](README.es.md)

**익숙한 Agent를 커리어 조언자로: 먼저 당신을 파악하고, 목표를 매일 할 수 있는 일로 나눕니다.**

AI는 여러 버전의 나를 상상하게 합니다. 履迹은 그 상상을 매일의 일정으로 옮깁니다.

이 문장을 Agent에 보내세요(Claude Code, Codex, Cursor 등 로컬 파일을 읽고 쓸 수 있는 Agent):

```text
请从 https://github.com/siliviasilivia85-lang/lvji-career-kit 安装并启用这个 Skill，先陪我梳理一段经历。
```

[설치 방법과 지원 환경](references/install.md) · 한 번 설치한 뒤에는 필요한 일을 말하면 됩니다.

이렇게 돕습니다:

1. **먼저 당신을 파악합니다:** 이력서, 지금 하는 일, 해 본 프로젝트를 읽고, 당신이 확인할 수 있는 기록으로 정리합니다.
2. **함께 목표를 정합니다:** 승진, 프로젝트 리드, 새 기술 학습, 새 방향 시도 모두 가능합니다. 아직 정리되지 않았어도 먼저 이야기할 수 있습니다.
3. **매일 할 일로 나눕니다:** 이번 주에 실제로 낼 수 있는 시간에 맞춰 일정을 잡습니다. 바쁘면 한 걸음을 줄이면 되며, 처음부터 다시 짤 필요는 없습니다.
4. **지난번 이어서 계속합니다:** 끝난 일은 당신이 확인한 뒤에 남깁니다. 다른 대화에서도 지난번에 멈춘 지점부터 이어 갑니다.

## LüJi를 만드는 이유

AI는 배우고 직접 해 보는 일의 문턱을 낮추고 있습니다. 한 사람이 시도할 수 있는 일이 늘고, 서로 다른 직무에 속하던 역량이 교차하고 결합하면서 커리어의 경계도 달라지고 있습니다. 다만 선택지가 늘어난다고 방향까지 선명해지는 것은 아닙니다. 시간은 여전히 한정되어 있고, 무엇을 배울 가치가 있는지, 어떤 프로젝트를 해야 하는지, 과거 경험을 어디에 쓸 수 있는지는 시도하며 조금씩 보이게 됩니다.

커리어 발전은 구직할 때만 일어나지 않습니다. 승진, 더 큰 책임, 새로운 분야로의 이동에도 평소의 축적이 필요합니다. 이런 질문을 AI에 가져가는 일에는 이미 익숙합니다. 이야기를 듣고 분석을 도울 수 있습니다. 하지만 생각이 흩어진 대화에만 남아 있으면 Agent가 참고할 수 있는 것도 그때 말한 일부뿐입니다. 조언은 일반적인 분석에 머물기 쉽고, 대화나 도구를 바꾸면 다시 처음부터 설명해야 합니다.

LüJi는 커리어를 키우는 방법, 자료 위치, 파일 도구를 하나의 Skill로 묶어 평소 쓰는 Agent에 맡깁니다. 이미 가진 경험과 역량에서 출발해 방향을 함께 논의하고, 목표에 필요한 지식과 실천을 나눈 뒤, 매일 낼 수 있는 시간에 맞춰 넣습니다. 당신이 확인한 산출물, 학습 기록, 실제 피드백은 저장됩니다. 기록이 쌓일수록 경험, 선호, 현실적인 제약을 더 구체적으로 이해하게 되며, 그 이해는 언제든 살펴보고 보충하고 바로잡을 수 있습니다.

## LüJi는 이렇게 작동합니다

### 과거: 이미 가진 경험을 정리하고 실제 근거를 남깁니다

예전 이력서, 업무와 프로젝트 자료, 학습 노트, 학력과 수상 기록을 Agent에 주거나 작업공간의 자료 폴더에 직접 넣습니다. Agent는 주제별로 정리하고 원본과 출처를 보존하며 구체적인 경험을 추립니다. 빠진 내용을 보충하거나 이해를 바로잡는 일은 언제든 할 수 있습니다.

과거의 계획, 실제로 한 일, 확인된 결과물은 구분해 기록합니다. 개인의 특성이나 역량을 정리할 때는 Agent가 실제 자료에 근거한 판단을 제시하고, 당신이 확인하고 고칩니다. 그 판단은 새로운 실천이 쌓이면 달라질 수도 있습니다.

### 현재: 목표를 일상의 업무와 학습으로 나눕니다

눈앞의 업무, 해 보고 싶은 프로젝트, 아직 분명하지 않은 방향에서 시작할 수 있습니다. Agent는 기존 경험, 현재 진도, 목표가 요구하는 것, 쓸 수 있는 시간을 함께 고려해 보완할 지식과 실천을 찾고, 구체적인 프로젝트, 단계별 결과, 일·주·월 행동으로 나눕니다.

학습 진도, 업무 산출물, 피드백은 차례로 덧붙일 수 있습니다. 계획을 볼 때는 기존 일정을 이어 가고, 조금 조정할 때는 관련된 항목만 바꿉니다. 시간이 부족하거나 목표가 달라지거나 진행이 막히면 범위를 줄일지, 미룰지, 잠시 멈출지, 계속할지를 함께 결정합니다. 과거 기록이 완전하지 않아도 시작할 수 있습니다.

### 미래: 발전 방향을 탐색하고 커리어 변화에 대비합니다

승진에 도전하거나, 새로운 책임을 맡거나, 다른 직무로 옮기거나, 자신의 프로젝트를 시도하고 싶다면 그 방향과 당시의 생각부터 남길 수 있습니다. 정해진 JD가 없어도 목표를 논의할 수 있습니다. 구체적인 직무를 살펴볼 때는 요구 사항을 모으고 방향과 회사별 차이를 비교한 뒤, 기존 경험과 현재의 축적에 연결해 근거, 부족한 점, 더 알아볼 질문을 정리합니다.

실제로 구직 단계에 들어가 여러 방향, 여러 이력서 버전, 면접, 진행 상황을 동시에 살펴야 할 때도 같은 축적을 그대로 쓸 수 있습니다.

- **이력서 제작:** 직무와 회사에 맞는 경험과 확인된 결과물을 골라 독립된 버전의 웹 이력서를 만듭니다. 레이아웃은 여섯 가지이며, 지정한 사진을 쓰거나 사진 없이 만들 수 있습니다. 해당 웹 버전을 검토한 뒤, 설치된 Chrome/Chromium으로 같은 버전의 PDF를 내보냅니다.
- **면접 준비:** 프로젝트 경험 이야기, 직무 질문, 전달 요점을 정리합니다. 회사와 면접 차수에 맞춰 자료를 준비하고, 질문별로 연습하며, 실제 면접 후 회고도 남깁니다.
- **지원 기회 관리:** 회사와 직무별 지원 단계, 실제로 사용한 이력서 버전, 피드백, 다음 할 일을 기록합니다. 전체 진행을 보거나 한 직무·기회만 볼 수 있습니다. 실제 피드백을 현재로 가져와 새로운 연습과 행동 제안으로 연결할 수도 있습니다.

### 계속 사용하기: 대화가 다음 대화로 이어지게 합니다

경험, 행동, 계획, 결과물은 읽을 수 있는 로컬 파일에 저장합니다. 사용자와 Agent는 각자 자료 지도를 갖습니다. 새 자료는 폴더에 직접 넣을 수 있고, Agent는 관련 질문을 처리할 때 그 범위의 변화를 확인해 필요한 내용을 읽습니다. 중요한 내용은 먼저 구체적인 초안으로 만든 뒤, 당신이 확인한 다음에 남깁니다.

다른 대화로 옮겨 가면 Agent는 저장된 항목 요약에서 목표, 멈춘 지점, 다음 할 일을 찾아 이어 갑니다. 사용자를 이해하는 근거는 저장하기로 선택한 경험, 결과물, 대화의 결론입니다. 저장하지 않은 대화는 장기 기억으로 취급하지 않습니다. 출처를 확인하고 기록을 고칠 수 있으며, 이해한 내용도 조정할 수 있습니다.

## 시작하기: 익숙한 경험 하나부터 정리합니다

처음에는 잘 아는 경험 하나를 고르세요. 해 본 프로젝트, 한동안의 업무, 하나의 학습이면 됩니다. 기존 이력서의 일부, 프로젝트 회고, 학습 노트면 충분합니다. 문서가 없다면 있었던 일을 적어도 됩니다. 처음부터 완전한 경력 자료를 준비할 필요는 없습니다.

아직 과거 자료가 없어도 지금 하고 싶은 일부터 이야기할 수 있습니다. 경험은 나중에 보충할 수 있고, 아직 정하지 않은 생각만 따로 남길 수도 있습니다.

1. **설치하고 작업공간을 만듭니다.** 맨 앞의 문장을 Agent에 보내세요. Skill을 설치합니다. 자료를 저장해야 하면 설치 폴더 밖에 개인 작업공간을 만듭니다(새 사용자는 `~/lvji-workspace/`를 권장). 선택한 중국어 또는 영어로 첫 안내와 자료 지도를 생성합니다. 중국어 입구는 `从这里开始.md`, 영어는 `START-HERE.md`입니다. 처음 한 번만 하면 되고, 이후에는 평소처럼 대화하면 됩니다. 이미 로컬에 내려받은 경우에는 현재 폴더에서 설치해 달라고 할 수도 있습니다. 전체 파일 작업에는 로컬 파일을 읽고 쓰고 실행할 수 있는 Agent와 Python 3.10+가 필요합니다.
2. **그 경험의 자료를 넣습니다.** 작업공간의 `past/materials/`에 넣고, 분류가 애매하면 `inbox/`를 사용합니다. 첨부파일을 Agent에 주고 가져와 정리해 달라고 할 수도 있습니다. 직접 넣은 원본은 이름과 위치를 유지합니다. 일반 메모, PDF, Word, 이미지에 내부 필드를 작성할 필요는 없습니다. 첨부파일을 정확히 이해할 수 있는지는 사용하는 Agent에 따라 달라집니다.
3. **함께 정리하고 확인합니다.** Agent가 무엇을 했고, 어떤 역할을 맡았으며, 무엇을 남겼는지 추려 경험 초안을 만들고, 근거와 아직 확인할 점을 표시합니다. 빠진 내용을 보충하고 이해를 고친 뒤 확인하면, 읽을 수 있는 Markdown 기록으로 저장됩니다. 원본은 그대로 남습니다. 기록 본문은 직접 고칠 수도 있습니다. 작업 날짜와 상태는 별도 필드를 쓰므로 Agent에 조정을 맡기는 편이 간단합니다.
4. **개요에서 한 번 봅니다.** Agent에 작업 화면을 생성해 보여 달라고 하세요. 「개요 → 과거와 현재의 이해」에서 방금 정리한 기록을 열어 본문과 출처를 확인합니다. 정확하지 않은 부분은 Agent에 수정을 요청하거나 Markdown을 직접 고친 뒤 페이지를 다시 생성합니다. 웹페이지는 현재 조회와 선택을 위한 것이며, 수정은 Agent나 파일로 하고 페이지 안에서 직접 저장하지는 않습니다.
5. **이 축적에서 다음 걸음을 잇습니다.** 지금 하고 싶은 일과 낼 수 있는 시간을 바탕으로 진행할 만한 프로젝트나 행동을 논의합니다. 미래 방향과 연결해도 되고 독립적으로 진행해도 됩니다. 저장을 결정한 뒤에는 통합 계획에서 일정을 확인할 수 있습니다.

첫 정리가 끝나면 원본이 어디에 있는지, 정리된 기록을 읽고 바로잡을 수 있는지, 다음 대화를 여기서 이어 갈 수 있는지를 알 수 있어야 합니다. 가상 자료로 먼저 익히고 싶다면 Agent에 [체험 안내](examples/try-it.md)를 따라 새 임시 폴더에서 진행해 달라고 요청하세요.

## 자주 묻는 질문

**어떤 Agent가 필요한가요?** 로컬 파일을 읽고 쓰고 실행할 수 있는 Agent입니다. Claude Code, Codex, Cursor 등. 파일 도구에는 Python 3.10+가 필요합니다. 대화만 가능한 환경에서도 논의와 초안은 할 수 있지만, 로컬 저장까지 마치지는 못합니다. 환경별 상황은 [호스트 안내](references/hosts.md)를 보세요.

**API 키가 필요한가요?** 별도의 모델 키는 필요 없습니다. LüJi는 사용 중인 Agent의 대화와 도구 능력을 다시 씁니다. 로컬 파일 도구는 모델을 호출하지 않습니다.

**내 자료는 어디에 있나요?** 컴퓨터의 개인 작업공간에 읽을 수 있는 Markdown 파일로 있으며, 소스와 함께 공개되지 않습니다. 대화 내용은 사용 중인 Agent의 방식대로 해당 모델 서비스로 전송됩니다.

**이력서가 없어도 쓸 수 있나요?** 가능합니다. 지금 하고 싶은 일부터 이야기하고, 경험은 나중에 보충하면 됩니다.

**구직을 준비하는 사람에게만 맞나요?** 아닙니다. 승진, 프로젝트 리드, 새 기술 학습, 새 방향 시도도 눈앞의 업무에서 시작할 수 있습니다.

**다른 대화로 가면 기억하나요?** 저장하기로 선택한 내용은 기억합니다. 경험, 결과물, 결정, 항목 요약입니다. 저장하지 않은 대화는 장기 기억으로 취급하지 않습니다.

**매일 할 일을 알려 주나요?** 현재 내장된 백그라운드 알림이나 실시간 동기화는 없습니다. 필요할 때 작업 화면을 열거나, 오늘 무엇을 할지 Agent에 물으면 됩니다. 알림 기능은 호스트에 달려 있습니다.

**이력서 지원이나 채용 담당자 연락을 대신하나요?** 하지 않습니다. 지원 진행은 당신이 알려 준 실제 사건만으로 업데이트합니다.

| 예전 이력서, 증명서, 과거 업무·프로젝트 자료, 학습 노트 | `past/materials/`; 주제별 하위 폴더를 만들어도 됩니다 |
| 현재 공통 자료, 또는 진행 중인 항목의 자료 | `present/materials/` 또는 `present/items/<item>/materials/` |
| 아직 소속을 정하지 않은 JD나 방향 자료 | `future/materials/` |
| 특정 방향이나 회사 기회에 관한 JD, 스크린샷, 피드백 | 해당 방향 또는 기회의 `materials/` |
| 아직 어떻게 분류할지 모르는 내용 | `inbox/` |

작업공간의 `MAP.md`는 사람을 위한 자료 지도이고, `AGENT-MAP.md`는 Agent의 읽기 안내입니다. 둘 다 같은 목록에서 나옵니다. 파일은 직접 넣으면 됩니다. Agent는 다음 관련 질문을 처리할 때 그 범위의 변화를 확인하고, 필요한 내용을 읽은 뒤 정리 결과를 함께 검토합니다. 파일을 발견하는 것, 자료를 이해하는 것, 경험을 확인하는 것은 서로 다른 단계입니다.

구역 설명, 자료 지도, 첫 입구는 중국어 또는 영어로 생성됩니다. 실제 경로는 `past/`, `present/`, `future/`로 유지되며, 지도는 선택한 언어로 어디에 무엇을 두는지 설명합니다. 직접 만드는 파일 이름과 하위 폴더에는 한국어를 쓸 수 있습니다. 언어나 Agent를 바꿔도 기존 참조와 버전이 이어지며, 자료를 옮길 필요는 없습니다.

<summary><strong>지금은 어떤 화면이 있나요</strong></summary>

**주 작업 화면은 같은 웹페이지의 네 가지 보기이며, 개인 작업공간의 `views/overview.html`에 함께 생성됩니다.** 이 파일 하나를 열고 상단 탭으로 전환합니다.

| 보기 | 확인할 수 있는 내용 | 이어서 할 곳 |
| --- | --- | --- |
| **개요** | 진행 중인 항목, 오늘의 행동, 최근 학습과 업무 진전, 펼쳐 볼 수 있는 완료·일시 중지 항목, 생각, 단계별 회고 | 항목과 출처를 엽니다. 과거 기록은 「과거와 현재의 이해」에서 펼칩니다 |
| **통합 계획** | 일별 행동, 주간 달력, 월간 달력, 연간 월 카드, 관련 계획 설명과 실제 기록 | 시간 단위를 바꾸고 행동을 봅니다. 일정을 바꿔야 하면 Agent에게 맡깁니다 |
| **방향** | 가로로 배열된 커리어 방향, 관련 요구와 근거 뒷받침, 자료 충실도, 개인 선호 | 정렬해 비교하고, 방향과 회사 JD 상세로 들어가 이력서와 면접 자료를 봅니다 |
| **지원 현황** | 각 회사 기회의 단계, 다음 할 일, 이력, 실제로 사용한 이력서 버전, 피드백 | 모든 기회를 보거나 방향·회사·기회·단계로 필터합니다. 사용한 버전이 기록되지 않았으면 비어 있음을 분명히 남깁니다 |

독립 패널로 오해하기 쉬운 내용도 있습니다.

- **과거 경험**은 개요 안에서 펼칩니다. 지금은 별도의 최상위 「과거」 페이지가 없으며, 원본과 정리 상태는 `MAP.md`에서 찾습니다.
- **면접 자료**는 방향 또는 지원 현황의 상세 안에서 엽니다. 별도의 면접 홈페이지는 없습니다.
- **웹 이력서**는 독립 저장된 HTML입니다. 직무 공통판은 `future/roles/<role>/common/resumes/<version>/`, 회사판은 해당 기회의 `resumes/<version>/`에 있습니다. 상세의 「기존 이력서 버전」에서 들어갑니다. 여섯 가지 템플릿은 여섯 가지 레이아웃이며, 여섯 개의 작업 화면이 아닙니다.

페이지는 저장된 파일에서 필요할 때 생성됩니다. 필터, 정렬, 조회는 페이지 안에서 할 수 있습니다. 본문, 작업 날짜, 지원 상태를 바꿀 때는 Agent가 차이를 보여 주고, 확인한 뒤 새로고침하거나 Markdown을 직접 고칩니다. 「Agent에게 조정을 요청」은 요청 문구를 복사하는 호환용 입구입니다. 일상적으로 페이지에서 지시문을 복사할 필요는 없습니다. 현재 페이지는 자료를 직접 다시 쓰지 않으며, 드래그로 일정을 저장하는 기능도 없습니다.

필터는 눈앞의 표시만 바꿉니다. 전체 스냅샷에는 생성 시 읽어 온 커리어 자료가 들어 있으며, 직무별로 격리된 공유 링크가 아닙니다. 외부에 보여 줄 때는 포함할 범위를 분명히 한 별도 자료를 Agent에 만들어 달라고 하세요.

입구, 생성 방식, 실제로 지원하는 동작은 [시각화 안내](references/views.md)에 모여 있습니다. 템플릿 소스는 `assets/md_workspace.html`이며, 작업공간 데이터를 넣어야 쓸 수 있는 페이지가 됩니다. 자신의 자료를 찾으려고 템플릿을 직접 열 필요는 없습니다.

### 이력서 스타일은 먼저 미리 볼 수 있습니다

이력서를 만들기 전에 Agent에게 가상 스타일 갤러리를 만들어 달라고 할 수 있습니다. 같은 경험을 소개 사이드바, 고전 1단, 근거 아카이브, 간결한 텍스트, 프로젝트 우선, 경력 우선의 여섯 가지 레이아웃으로 보여 줍니다. AI가 만든 가상 인물 사진 두 장을 바꾸거나 사진을 빼 볼 수 있습니다. 고른 뒤에는 레이아웃 이름을 Agent에 알리고, 자신의 경험과 사진으로 바꿉니다.

갤러리에는 GitHub 웹 이력서 참고 7개도 있으며, 공식 예시, 쓰임, 라이선스 링크를 제공합니다. 내장된 여섯 레이아웃과 구분해 보여주는 외부 참고입니다. 입구와 생성 방법은 [이력서 흐름](references/resume.md)을 보세요.

<summary><strong>가상 데모 사이트</strong></summary>

로컬 데모의 대화는 가상 예시임을 분명히 표시합니다. 데모는 「경험 정리 → 방향 탐색 → 행동으로 나누기 → 축적 남기기」를 이은 뒤, 계획·방향·이력서를 열어 결과를 보여 줍니다. 데모 웹페이지 자체는 온라인 Agent를 실행하지 않으며 방문자의 자료도 저장하지 않습니다.

관리자는 정적 호스팅에 맞는 버전을 생성할 수 있습니다.

```text
python3 scripts/demo_site.py --output _site
```

출력 폴더는 새 폴더여야 합니다. 데모에는 가상의 읽기 전용 페이지와 로컬 자료만 들어가며, 컴퓨터 경로, 개인 작업공간, 실행 이력은 내보내지 않습니다. 저장소를 만든 뒤 Pages에서 GitHub Actions를 고르고 [데모 게시 워크플로](.github/workflows/pages.yml)를 수동 실행할 수 있습니다. `_site/`만 올리고, 저장소 전체나 커리어 자료 디렉터리는 공개하지 않습니다. 워크플로가 준비되었다고 이미 온라인 사이트가 있는 것은 아닙니다.

```text
└── .luji/               도구가 관리하는 초안, 이력, 탐색 캐시
```

경험과 행동은 각각 주 파일이 있고, 서로 다른 방향과 일·주·월 계획은 같은 축적을 참조합니다. 다른 대화에서는 Agent가 저장된 항목 요약에서 목표, 멈춘 지점, 다음 걸음을 찾습니다. 저장하지 않은 대화는 장기 기억으로 취급하지 않습니다. 원본 자료는 당신이 가지고 있으며, 정리된 파일도 보고 고칠 수 있습니다.

기록 본문은 직접 편집할 수 있습니다. 행동 날짜와 상태는 `scheduled_for`, `due_on`, `status` 메타데이터를 따릅니다. 본문의 날짜만 바꿔서는 일정이 바뀌지 않습니다. Agent에 부분 조정을 맡길 수 있고, 직접 고칠 때는 안정적인 ID, 올바른 JSON 값, 기존 이력을 유지하세요.

아직 목표라고 부르기 어려운 생각은 `present/notes/`에 둘 수 있습니다. 업무, 학습, 구직이 한 단락 끝나면 `present/stages/`에 단계 회고를 남겨 실제 결과를 인용하고, 선택이 어떻게 달라졌는지 기록한 뒤, 다음 단계로 무엇을 가져갈지 결정할 수 있습니다. 회고를 저장했다고 프로젝트를 자동 종료하거나 다음 할 일을 짜 주지는 않습니다.

새 대화에서는 자신의 작업공간을 바로 열 수 있습니다. 확인할 수 있는 Skill 위치가 기록되어 있습니다. 나중에 Skill 패키지를 옮겼다면 [탐색 연결 안내](references/navigation.md)에 따라 다시 연결해 달라고 Agent에 요청하면 됩니다. 커리어 자료를 다시 만들 필요는 없습니다.

<details>
<summary><strong>사용 범위와 현재 진행</strong></summary>

LüJi는 기존 Agent의 대화, 첨부 이해, 도구 능력을 다시 쓰며 별도의 모델 서비스를 붙이지 않습니다. 로컬 파일 도구에는 모델 키가 필요 없습니다. 완전한 경험은 호스트의 파일 읽기·쓰기·실행·표시 능력에 달려 있습니다. 페이지는 호스트의 파일 패널, 대화, 브라우저에서 볼 수 있으며, 현재는 생성 시각이 있는 로컬 스냅샷입니다.

이력서는 여섯 가지 레이아웃을 제공하며, 기본은 간결한 2단입니다. 사진은 선택 사항이고, 내용은 실제 출처를 유지합니다. 해당 웹 버전을 검토한 뒤 설치된 Chrome/Chromium으로 같은 버전의 PDF를 내보낼 수 있습니다. 면접 준비도 같은 경험과 결과물을 사용합니다. 자세한 내용은 [이력서 흐름](references/resume.md)과 [면접 흐름](references/interview.md)을 보세요. 지원 진행은 당신이 알려 준 실제 사건으로 업데이트하며, 이력서를 자동 보내거나 채용 담당자에게 연락하지 않습니다.

생성할 때마다 독립된 버전을 남깁니다. PDF 내보내기 확인은 그 정확한 버전과 파일에 묶입니다. 신뢰할 수 있는 확인이 없는 예전 PDF나 수동 파일은 미검증으로 표시합니다. 템플릿을 업데이트해도 온전한 과거 HTML이 무효가 되지는 않으며, 커리어 출처가 달라졌는지는 따로 알립니다. 지원 이력에는 실제로 사용한 이력서 파일을 연결할 수 있고, 모르면 기록되지 않음으로 남기며 최신 버전이라고 추정하지 않습니다.

README는 중국어 간체, 영어, 일본어, 한국어, 스페인어가 있습니다. 작업공간의 첫 안내와 사용 지도는 현재 중국어와 영어이며, 초기화 때 `zh` 또는 `en`을 선택합니다. Agent와는 자신의 언어로 대화할 수 있고, 실제 이해는 호스트에 달려 있습니다. 실제 디렉터리 이름은 호환을 유지합니다. 웹 작업 화면의 고정 문구는 지금도 주로 중국어이고, 운영 지침도 주로 중국어입니다. 이번 README 번역이 인터페이스 전체의 다국어화를 뜻하지는 않습니다.

현재 내장된 백그라운드 알림이나 실시간 동기화는 없습니다. 알림과 음성 등은 호스트에 달려 있습니다. 호스트별 필요 능력, 표시 대체 경로, 실제 검증 범위는 [호스트 안내](references/hosts.md)에 있습니다. 기존 형식의 작업공간은 보존하며 자동 이전하지 않습니다. 테스트와 미검증 항목은 [TESTING.md](TESTING.md)를 보세요.

</details>

체험 자료는 모두 가상입니다. 개인 커리어 자료는 소스와 함께 배포되지 않습니다. 페이지와 도구의 출처는 [ASSETS.md](ASSETS.md), 라이선스는 상업적 사용을 허용하는 [MIT](LICENSE)입니다.
